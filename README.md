# VidyaRAG (demo backend)

An exam-prep chatbot for JUIT students. It has two modes:

- **Ask:** grounded Q&A over the study material, with citations (subject, unit, topic, file, page). It replies *"Not found in the material."* when the material has no answer.
- **Generate:** new practice questions modelled on PYQ style. Each question goes through an answerability validator, and the questions that fail are shown as rejected.

## Quick start

```bash
cd vidyarag
uv venv --python 3.11 .venv && source .venv/bin/activate
uv pip install torch==2.5.1 --index-url https://download.pytorch.org/whl/cpu
uv pip install -r requirements.txt

cp .env.example .env              # then put your GROQ_API_KEY in .env
python scripts/make_sample_data.py   # sample PDFs (skip if you have real ones)
python scripts/build_index.py        # ingest + chunk + Chroma/BM25 indexes

uvicorn app.main:app --port 8000                 # terminal 1: API (docs at /docs)
streamlit run frontend/streamlit_app.py          # terminal 2: UI at :8501
```

Tests (no API key needed): `python -m pytest -q tests`
Evaluation: `python scripts/run_eval.py` (`--skip-ragas` for the LLM-free part only, `--limit 5` for a quick run)

## How it works

```
PDFs -> ingestion (PyMuPDF, clean, unit/topic/marks/year metadata)
     -> chunking (fixed | semantic | hierarchical)
     -> ChromaDB (bge-small embeddings) + BM25
     -> hybrid retrieval: Reciprocal Rank Fusion -> cross-encoder rerank
     -> LangGraph: router -> qa | generate(+validator)
     -> FastAPI -> Streamlit
```

- **Hybrid retrieval** ([app/retrieval/hybrid.py](app/retrieval/hybrid.py)): the top 10 from vectors and the top 10 from BM25 are fused with `1/(60+rank)`, then reranked by `ms-marco-MiniLM-L-6-v2`. The BM25 tokenizer keeps terms like `csma/cd`, `3nf` and `belady's` intact.
- **Grounding guard:** if the best reranker score is below `QA_MIN_SCORE` (−5), the answer is "not found" and the LLM is never called. Otherwise the prompt only allows answers from the numbered passages.
- **Hierarchical chunks:** the search runs over small child chunks (~300 chars), but the LLM receives the whole parent (unit, topic) section.
- **Validator** ([app/generation/validator.py](app/generation/validator.py)): each generated question is used to re-query the study material. If the best rerank score is below `ANSWERABLE_THRESHOLD` (0.0), the question is rejected.
- **PYQ topics:** PYQ papers rarely state a topic, so `build_index.py` tags each question with the closest study-material topic from the same subject and unit.

## Using real data

Put the PDFs in `data/raw/study_material/<subject>/` and `data/raw/pyqs/<subject>/`. The folder name becomes the subject: `operating_systems` → "Operating Systems", and short names like `dbms` are uppercased. Then rerun `build_index.py`.

The metadata parser expects:
- **Notes:** headings such as `Unit 2: Normalization` and `Topic: Normal Forms`. Text before the first `Topic:` is skipped.
- **PYQs:** `Q1. ... [5 marks] (Unit 2)`, with a year anywhere on the paper. `(Unit N)` is optional.

Real JUIT PDFs will likely need small regex tweaks in [app/ingestion/metadata.py](app/ingestion/metadata.py). Also add real questions to `data/eval/testset.json`.

## Defaults chosen (per the brief: pick and note)

- **LLM: `openai/gpt-oss-120b` on Groq.** The brief says Llama 3.3 70B, but `llama-3.3-70b-versatile` is no longer available on Groq (it returned `model_not_found`). Change `GROQ_MODEL` in `.env` to switch.
- **Embeddings:** `BAAI/bge-small-en-v1.5`, which is small and fast on CPU. **Reranker:** `cross-encoder/ms-marco-MiniLM-L-6-v2`.
- **Default chunking:** `hierarchical`, the best performer in `evaluation/results/chunking_comparison.csv`.
- **Sample data:** 3 subjects (DBMS, Operating Systems, Computer Networks). All files are generated by `scripts/make_sample_data.py` and marked SAMPLE. They are not real JUIT papers.
- **Vector-only baseline:** dense search with no BM25 and no reranker, i.e. "plain semantic search".
- **RAGAS:** the Groq model is the judge, and `ResponseRelevancy(strictness=1)` keeps free-tier calls down.
- **Python 3.11** venv: the existing 3.14 venv is too new for chromadb and torch.
